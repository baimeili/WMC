# 部署运维

本文档描述 WMC 的部署方式、配置、迁移、备份恢复、可观测性与故障排查。所有命令与默认值以仓库内代码/脚本为准：

- 配置加载：`backend/internal/platform/config/config.go`
- 启动入口：`backend/cmd/api/main.go`、`backend/cmd/seed/main.go`、`backend/cmd/devdb/main.go`
- 部署文件：`deploy/docker-compose.yml`、`deploy/Caddyfile`、`backend/Dockerfile`
- 脚本：`scripts/*.ps1`、`deploy/scripts/*.ps1`

## 1. 运行环境矩阵

| 环境 | 说明 | 数据库 | Redis | 对象存储 | 短信 |
|---|---|---|---|---|---|
| development | 本机开发，默认环境 | 本地 embedded PostgreSQL 18.3（无 Docker）或 compose PostgreSQL | 可空，自动降级内存实现 | fs 本地盘 | mock |
| staging | 预发，建议与生产同构 | PostgreSQL 18 | Redis 7 | S3 兼容 | 真实供应商（当前仅 mock 实现） |
| production | 生产 | PostgreSQL 18 | Redis 7 | S3 兼容（强制） | 禁止 mock |

生产环境启动时会强制校验以下项（任一不满足直接拒绝启动，见 `config.validate`）：

- `JWT_SECRET` 必须非空且长度 ≥ 32；
- `PHONE_HASH_SECRET` 必须非空；
- `PHONE_ENC_KEY` 必须是 base64 编码的 32 字节密钥；
- `SMS_PROVIDER` 不能是 `mock`；
- `STORAGE_DRIVER` 必须是 `s3`；
- `ADMIN_DEV_LOGIN_ENABLED` 必须是 false。

## 3. Docker Compose 部署

### 3.1 编排内容

`deploy/docker-compose.yml` 定义 5 个服务（project name: `wmc`）：

| 服务 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| postgres | postgres:18-alpine | ${POSTGRES_PORT:-5432}:5432 | 数据卷 pgdata；pg_isready 健康检查 |
| redis | redis:7-alpine | ${REDIS_PORT:-6379}:6379 | 开启 appendonly，数据卷 redisdata |
| minio | minio/minio:latest | ${MINIO_PORT:-9000}:9000、${MINIO_CONSOLE_PORT:-9001}:9001 | 控制台地址 :9001，数据卷 miniodata |
| backend | 由 `backend/Dockerfile` 构建 | ${BACKEND_PORT:-8080}:8080 | 依赖 postgres/redis healthy；容器内 DATABASE_URL 指向 postgres 服务 |
| caddy | caddy:2-alpine | ${CADDY_HTTP_PORT:-80}:80 | 反向代理与静态文件服务 |

启动：

```bash
# 在仓库根目录执行（推荐显式指定 compose 文件与 env 文件）
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build

# 或进入 deploy 目录（compose 默认读取当前目录的 .env）
cd deploy
cp .env.example .env
docker compose up -d postgres redis minio   # 仅启动基础设施
docker compose up -d --build                # 启动全部服务
```

查看状态/日志/停止：

```bash
docker compose -f deploy/docker-compose.yml ps
docker compose -f deploy/docker-compose.yml logs -f backend
docker compose -f deploy/docker-compose.yml down        # 停止但保留数据卷
docker compose -f deploy/docker-compose.yml down -v     # 停止并删除数据卷（危险）
```

### 3.2 反向代理（Caddyfile）

`deploy/Caddyfile` 监听 `:80`：

- `/api/*`、`/health/*`、`/metrics` → `backend:8080`；
- `/admin/*` → `/srv/static/admin`（SPA 回退 index.html）；
- 其他路径 `/` → `/srv/static/h5`（SPA 回退 index.html）。

静态文件挂载：`deploy/static` → 容器 `/srv/static:ro`。部署前需准备：

```bash
# 构建产物放到 Caddy 挂载目录
# H5：app/uni-app 执行 npm run build:h5 后，把 dist/build/h5 复制到 deploy/static/h5
# 运营后台：admin/vue-admin 执行 npm run build 后，把 dist 复制到 deploy/static/admin
mkdir -p deploy/static/h5 deploy/static/admin
```

- 本机未安装 Docker（`docker` 命令不存在），docker compose **未实跑**，属于**待验证**项。

## 4. 无 Docker 环境：嵌入式 PostgreSQL

本机没有 Docker 时可使用 `github.com/fergusstrange/embedded-postgres` 启动便携版 PostgreSQL。

### 4.1 实际环境（已实测）

- PostgreSQL 版本：**18.3**（`postgres (PostgreSQL) 18.3`）；
- 监听端口：**55432**；
- 数据目录：**`backend/.data/pg`**（脚本在 backend 工作目录下执行，相对路径 `.data/pg` 实际落在 backend 下）；
- 二进制来源：`https://maven.aliyun.com/repository/public`（首次运行自动下载并缓存，约 150 MB 以上；repo1.maven.org 在本机不可达）；
- 连接串：`postgres://wmc:wmc_local_password@localhost:55432/wmc?sslmode=disable`；
- 进程形态：`backend/.data/pg/bin/bin/postgres.exe -D backend/.data/pg/data -p 55432`。

### 4.2 使用方式

```powershell
# 首次运行会下载 PostgreSQL 二进制并初始化数据目录；保持前台运行
pwsh ./scripts/dev-db.ps1
# 或等价地：
cd backend
go run ./cmd/devdb -port 55432 -data .data/pg

# 看到输出后，另开终端配置连接串并启动后端：
$env:DATABASE_URL = "postgres://wmc:wmc_local_password@localhost:55432/wmc?sslmode=disable"
cd backend
go run ./cmd/api
```

devdb 参数/默认值：`-port`（55432）、`-data`（.data/pg）、`-user`（wmc）、`-password`（wmc_local_password）、`-database`（wmc）、`-repo`（PG_BINARY_REPO 或阿里云 Maven）。按 Ctrl+C 优雅停止，数据保留在数据目录，下次启动直接复用。

注意：

- 便携版二进制只带 `postgres.exe` / `initdb.exe` / `pg_ctl.exe` 等服务端工具，**不含 pg_dump/psql**，备份恢复需另装客户端工具（见 §6）。
- `backend/.data` 目录目前未被 `.gitignore` 覆盖（根目录只忽略了 `/.data/`），提交前需确保不把 170 MB 以上的数据目录提交入库；建议补充忽略规则（**待修复**）。
- 对象存储驱动已实现两套：fs（本地盘 + 媒体代理签名 URL）与 s3（AWS SDK v2，支持 MinIO/OSS/COS 路径风格）；生产强制 s3。
- `EMBEDDED_PG` 配置项当前未接入 cmd/api 自动启动逻辑，必须先单独启动 devdb 再启动 API。

## 5. 数据库迁移与回滚

### 5.1 自动迁移

`MIGRATE_ON_START=true`（默认）时，`cmd/api` 与 `cmd/seed` 启动都会执行 goose 迁移；迁移文件通过 `backend/db/embed.go` 内嵌进二进制，无需在运行环境携带 SQL 文件。

### 5.2 手动迁移（goose）

```powershell
# 仓库封装脚本（默认连接 localhost:55432）
pwsh ./scripts/migrate.ps1 up
pwsh ./scripts/migrate.ps1 status
pwsh ./scripts/migrate.ps1 version
pwsh ./scripts/migrate.ps1 down     # 回滚最近一个版本（仅开发）
pwsh ./scripts/migrate.ps1 reset    # 回滚全部（仅开发/测试，危险）

# 直接调用 goose（已安装 v3.29.0：%USERPROFILE%\go\bin\goose.exe）
goose -dir backend/db/migrations postgres "$env:DATABASE_URL" up
```

迁移文件：`00001`~`00007`，内容详见 `docs/02-数据库设计.md`；版本记录在 `goose_db_version` 表。

### 5.3 发布流程建议

1. 先备份数据库（§6）；
2. 执行迁移（手动或由新版本启动自动执行，二选一，避免多实例并发迁移）；
3. 健康检查通过后接入流量；
4. 回滚代码时评估是否需要回滚 Schema：`goose down` 只回滚最近一个版本，跨多版本回滚需逐次执行；生产回滚优先「恢复备份/前向修复」，不要轻易 `reset`。

### 5.4 迁移失败排查

- `connect: connection refused`：数据库未启动或端口/DSN 错误（本地 devdb 默认 55432，compose 默认 5432）；
- 版本不连续：确认 `goose_db_version` 中最大版本号与迁移文件一致；
- 重复执行报「已存在」：迁移已应用，用 `status` 查看而不是重复执行；
- 回滚顺序错误：`00002`~`00006` 依赖 `00001` 的 users 表，必须按逆序回滚。

## 6. 备份与恢复

### 6.1 策略

- 每日全量备份；每周日额外标记为周备份；
- 保留 **7 个日备份 + 4 个周备份**（脚本默认 `-KeepDaily 7 -KeepWeekly 4`）；
- 格式：PostgreSQL custom format（`--format=custom`），可选择性恢复；
- 默认输出目录：`deploy/backups`；文件命名 `wmc_daily_YYYYMMDD_HHmmss.dump` / `wmc_weekly_YYYYMMDD_HHmmss.dump`；
- 生产建议：备份上传对象存储（当前脚本只落本地，上传逻辑**待实现**），并定期演练恢复。

### 6.2 备份命令

```powershell
cd D:\ai_workspace\WMC
pwsh ./deploy/scripts/backup.ps1 \
  -DatabaseUrl "postgres://wmc:wmc_local_password@localhost:55432/wmc?sslmode=disable"
```

脚本优先使用 PATH 中的 `pg_dump`；找不到时回退到 `docker compose exec postgres pg_dump`。本机既无 `pg_dump` 也无 Docker，因此在本机该脚本**未实测通过**（待验证）；如需本地备份，请安装 PostgreSQL 客户端工具并将 `pg_dump` 加入 PATH。

### 6.3 恢复命令

```powershell
pwsh ./deploy/scripts/restore.ps1 \
  -File deploy/backups/wmc_daily_20260101_030000.dump \
  -DatabaseUrl "postgres://wmc:wmc_local_password@localhost:55432/wmc?sslmode=disable"
```

恢复使用 `pg_restore --clean --if-exists --no-owner --no-privileges`，会**先删除同名对象再重建**，属于破坏性操作：务必确认目标库正确、最好在空库或演练库执行。

已知限制：

- 无 `pg_restore` 且无 Docker 时，脚本的容器回退分支通过 PowerShell 文本管道传递 dump，可能损坏二进制格式，不应用于生产；请安装客户端工具。
- 恢复后需要重新执行迁移到目标版本（若备份版本落后），并核对 `goose_db_version`。
- 演练建议：在独立库恢复 → `SELECT count(*) FROM users;` 等抽查 → 应用只读验证后删除演练库。

## 7. 健康检查与指标

### 7.1 健康检查

| 端点 | 说明 | 实测响应（2026-11-01，本机） |
|---|---|---|
| `GET /health/live` | 进程存活检查，不访问依赖 | `{"code":"OK","message":"","data":{"status":"ok"},"request_id":"..."}` |
| `GET /health/ready` | 就绪检查：数据库 Ping + 限流存储 Ping | `{"code":"OK","message":"","data":{"database":"ok","redis":"memory","status":"ready"},"request_id":"..."}` |
| `GET /metrics` | Prometheus 指标 | 见 §7.2 |

就绪失败时返回 HTTP 500（统一错误响应，code `INTERNAL`，message「依赖未就绪」），并同步更新 `wmc_db_up` / `wmc_redis_up` 指标。编排/负载均衡应使用 `/health/ready` 作为就绪探针、`/health/live` 作为存活探针。

### 7.2 Prometheus 指标

自定义指标（`backend/internal/platform/metrics/metrics.go`）：

| 指标 | 类型 | 标签 | 说明 |
|---|---|---|---|
| wmc_http_requests_total | Counter | method, route, status | HTTP 请求总数（含错误率统计） |
| wmc_http_request_duration_seconds | Histogram | method, route | 请求耗时（桶 5ms~5s） |
| wmc_http_inflight_requests | Gauge | - | 处理中的请求数 |
| wmc_db_up | Gauge | - | 数据库可用性（1/0） |
| wmc_redis_up | Gauge | - | Redis 可用性（1/0） |
| wmc_db_pool_conns | GaugeVec | state（acquired/idle/total/max） | 连接池状态 |

另注册 Go runtime 与 process 采集器。指标路由在根路径 `/metrics`（不带 `/api/v1` 前缀）。

## 8. 日志

- 使用标准库 `log/slog` 的结构化 JSON 输出到 stdout，级别由 `LOG_LEVEL` 控制；
- 访问日志字段：`request_id`、`method`、`path`、`status`、`latency_ms`、`bytes`（4xx warn、5xx error）；
- 请求 ID 来自 `X-Request-Id` 请求头（缺失或超长则生成 UUID），并在响应头回写；
- 启动/关闭日志：监听地址、环境、优雅关闭；
- 错误日志：`error_code`、`path`、`error`（不含请求体）。

**严禁输出**的敏感信息：

- 手机号明文（`logx` 的敏感键集合包含 phone/mobile 等，禁止新增直接拼接日志）；
- JWT / Access Token / Refresh Token / 验证码；
- 完整个人资料、请求 Body、密码、密钥。

已有实现：mock 短信只记录手机号后 4 位（`phone_suffix`）；`logx.Redact` 可对属性键脱敏。新增日志代码评审时必须检查字段白名单。

## 9. 限流策略

| 项 | 当前实现 |
|---|---|
| 存储 | `redisx.Store`：Redis（RATE_LIMIT_STORE=redis/auto 且可用）或内存实现（memory/降级） |
| 算法 | 固定窗口计数：key = `rl:<scope>:<client_ip>:<YYYYMMDDHHMM>`，窗口 1 分钟 |
| 公开与登录用户接口 | 公开路由组（含登录用户子组）统一挂 `limiter.Middleware("public", 120, time.Minute)`：同一 IP 每分钟最多 120 次 |
| 管理接口 | 当前**未挂**限流中间件（待补充，生产建议在 Caddy/网关层加限制） |
| 短信发送 | 已实现（`POST /api/v1/auth/sms/send`）：同一手机号 60 秒冷却、每日最多 5 次（均取自 system_settings，可后台调整）；同一 IP 每小时最多 30 次；验证码有效期 5 分钟 |
| 短信校验 | 已实现（`POST /api/v1/auth/sms/verify`）：同一手机号 10 分钟内最多尝试 10 次；校验通过后首次登录自动注册并激活账号 |
| 失效策略 | 限流存储异常时「放行」以免影响主流程；降级到内存实现仅适用于单实例开发环境 |
| 客户端 IP | 优先 `X-Forwarded-For` 第一个地址，其次 `X-Real-Ip`，最后 RemoteAddr；反向代理必须正确设置这两个头 |

## 10. 故障排查

| 现象 | 排查 |
|---|---|
| 启动报「必须配置 DATABASE_URL」 | 未设置环境变量；本地用 `pwsh ./scripts/dev-db.ps1` 启动 devdb 后设置 DSN |
| 启动报数据库不可用 | 确认 devdb/compose postgres 已启动、端口（55432/5432）与 DSN 一致、防火墙放行 |
