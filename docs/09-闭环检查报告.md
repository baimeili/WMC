## 4. 本轮发现的问题与处理

| # | 问题 | 类型 | 处理 |
|---|---|---|---|
| 1 | 冒烟脚本把「屏蔽后双向候选总数=0」当作断言 | 测试误判（其他候选人存在） | 改为断言「B 从候选列表消失且总数不增加」 |
| 2 | 候选人详情页 `conflicts/reasons/dimensions` 空数组被后端 `omitempty` 省略，前端取 `.length` 抛错 | 真实缺陷 | 后端固定输出数组 + 前端安全数组兜底 |
| 3 | 候选人卡片 `tap` 事件与原生冒泡冲突，详情页 `id=undefined` | 真实缺陷 | 组件事件改名 `select` + `@tap.stop` |
| 4 | H5 全站公共样式被 uni-app 作用域化，设计系统失效 | 真实缺陷 | 全局样式迁到 `src/styles/global.scss`，由 `App.vue` 引入 |
| 5 | 理论结果接口嵌套层级与前端契约不一致 | 真实缺陷 | 后端响应内嵌 `Estimate` 字段平铺 |
| 6 | 真实漏斗最终值显示单向人数，与末层双向人数矛盾 | 真实缺陷 | 最终块改为「双向基础候选人」 |

> 说明：2-6 已在 `6e4304f` 及之前的提交中修复并回归；本轮闭环检查未发现新的产品缺陷。

## 6. 结论

- **业务闭环成立（开发环境）**：游客计算 → 注册登录 → 完善资料 → 入池 → 双向候选池 → Like/Pass → Match → 结果反馈 → 后台指标/举报处理，全链路 46/46 冒烟通过。

- **生产部署闭环待验证**：Docker/真实 Redis/S3/短信/移动端打包属于环境依赖项，已在 README 与 docs/05 给出步骤与验收方法。
