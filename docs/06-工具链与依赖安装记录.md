## 3. Go 工具链行为

- `backend/go.mod` 声明 `go 1.26.0`，而本机安装的 Go 为 1.25.6，`GOTOOLCHAIN=auto` 会自动下载并使用 go1.26.0 工具链编译（首次运行输出 `go: downloading go1.26.0 (windows/amd64)`）。
- 工具链缓存在 `C:\Users\bml77\go\pkg\mod\golang.org\`，实际存在 `toolchain@v0.0.1-go1.26.0.windows-amd64` 与 `toolchain@v0.0.1-go1.26.10.windows-amd64` 两个版本。
- 安装 goose / sqlc 时，因为它们的 go.mod 要求 `go >= 1.26.0`，go 命令自动切换到 **go1.26.10** 工具链（日志：`requires go >= 1.26.0; switching to go1.26.10`）。
- 结论：**本机 `go version` 显示 1.25.6，但项目实际构建使用 Go 1.26 工具链**（`go env GOVERSION` 在 backend 目录输出 `go1.26.0`）。

## 6. sqlc 安装记录（源码编译失败 → 预编译二进制成功）

### 6.1 尝试一：源码安装（失败）

```powershell
go install github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1
```

- 日志：`.data/sqlc-build.log`（约 22 KB）；
- 过程：go 自动切换到 go1.26.10 工具链后开始编译，最终 CGO 链接失败；
- 关键错误（日志摘录）：
  - `running gcc failed: exit status 1`；
  - `C:/TDM-GCC-64/bin/../lib/gcc/x86_64-w64-mingw32/10.3.0/.../ld.exe: ... undefined reference to \`__stack_chk_fail' `；
  - `undefined reference to \`__stack_chk_guard' `；
  - `collect2.exe: error: ld returned 1 exit status`。
- 原因：sqlc 依赖 pg_query_go（CGO + C 代码），本机 TDM-GCC 10.3.0 与该 CGO 构建不兼容（缺少/无法链接 stack protector 符号）；同时源码全量编译对内存/页面文件占用较高。
- 结论：**Windows + TDM-GCC 环境下不建议源码编译 sqlc**。

### 6.2 尝试二：官方预编译二进制（成功）

- 下载 `sqlc_1.31.1_windows_amd64.zip`（官方 GitHub Releases 预编译包）；
- 下载产物：`C:\Users\bml77\AppData\Local\Temp\sqlc_dl2\sqlc.zip`（15,284,588 字节，2026-11-01 01:12:04）；
- 解压得到 `sqlc.exe`（57,725,440 字节），复制到 `C:\Users\bml77\go\bin\sqlc.exe`；
- 验证：`sqlc version` → `v1.31.1`；`Get-Command sqlc` → `C:\Users\bml77\go\bin\sqlc.exe`。
- 生成代码：`backend/internal/db/sqlcdb`（12 个文件），已提交入库；无 sqlc 时后端仍可编译。
- 重新生成命令（在 backend 目录）：`sqlc generate`（配置 `backend/sqlc.yaml`；生成目录 `internal/db/sqlcdb`）。

## 7. 本地 PostgreSQL（embedded-postgres）

- Go 依赖：`github.com/fergusstrange/embedded-postgres v1.34.0`；
- 启动命令：`pwsh ./scripts/dev-db.ps1`（等价 `cd backend; go run ./cmd/devdb -port 55432 -data .data/pg`）；
- 首次运行从 `PG_BINARY_REPO`（默认 `https://maven.aliyun.com/repository/public`）下载二进制并解压到 `backend/.data/pg/bin`；
- 实测版本：**PostgreSQL 18.3**（`postgres (PostgreSQL) 18.3`）；
- 数据目录：`backend/.data/pg/data`（目录大小约 170 MB）；端口 `55432`；
- 连接串：`postgres://wmc:wmc_local_password@localhost:55432/wmc?sslmode=disable`；
- 进程实测：`postgres.exe -D D:/ai_workspace/WMC/backend/.data/pg/data -p 55432`；
- 说明：该便携发行版**不含 `pg_dump`/`psql`** 等客户端工具，备份恢复需另装 PostgreSQL 客户端。

## 8. 前端依赖

### 8.1 npm 配置

仓库根、`app/uni-app`、`admin/vue-admin` 均有 `.npmrc`：

```ini
registry=https://registry.npmmirror.com
strict-peer-dependencies=false
auto-install-peers=true
fund=false
audit=false
```

- 原因：本机访问 `registry.npmjs.org` 超时（详见 §9），必须走 npmmirror；
- 已知现象：npm 11 会对 `strict-peer-dependencies`/`auto-install-peers` 输出 `Unknown project config` 警告（无害，pnpm 配置项对 npm 无意义）。

### 8.2 安装命令

```powershell
cd admin/vue-admin
npm install          # 生成/更新 package-lock.json，依赖来自 registry.npmmirror.com
npm run build

cd ../../app/uni-app
npm install
npm run build:h5
```

两个前端的 `package-lock.json` 内 `resolved` 字段均为 `https://registry.npmmirror.com/...`，可证明镜像生效。

## 9. 网络限制与镜像（2026-11-01 01:11 实测）

| 目标 | 结果 | 处理方式 |
|---|---|---|
| https://registry.npmjs.org/ | 超时（HEAD 8s 无响应） | 改用 `https://registry.npmmirror.com` |
| https://registry.npmmirror.com/ | 200（`npm ping` → PONG） | 作为 npm registry |
| https://repo1.maven.org/maven2/ | 超时（8s 无响应） | 改用 `https://maven.aliyun.com/repository/public`（200） |
| https://maven.aliyun.com/repository/public/ | 200 | embedded PostgreSQL 二进制下载源 |
| https://raw.githubusercontent.com/ | 超时（8s 无响应） | 不依赖 raw 内容；SQL/文档均在仓库内 |
| GitHub Releases（sqlc 预编译包） | 实测可下载（sqlc.zip 15.28 MB） | sqlc 安装回退方案 |
| Go module proxy | 使用默认 GOPROXY（未显式改配置），依赖下载正常 | `go env GOPROXY` 未覆盖 |

结论：本机必须使用国内镜像；npm 与 Maven 均有可用镜像，raw.githubusercontent.com 不可用。

## 11. 失败与回退方案

| 问题 | 失败现象 | 回退/解决方案 | 当前状态 |
|---|---|---|---|
| npm 官方源不可达 | 安装/查询超时 | 项目级 `.npmrc` 指向 npmmirror | 已解决 |
| Maven Central 不可达 | embedded PostgreSQL 二进制下载失败 | `PG_BINARY_REPO=https://maven.aliyun.com/repository/public` | 已解决（PG 18.3 实测启动） |
| sqlc 源码编译 | CGO/TDM-GCC 链接失败（`__stack_chk_fail` 未定义） | 下载官方预编译 `sqlc_1.31.1_windows_amd64.zip`，解压后放入 `%USERPROFILE%\go\bin` | 已解决（sqlc v1.31.1 可用） |
| goose 源码安装要求新 Go | 首次触发 go1.26.10 工具链下载 | 保持 `GOTOOLCHAIN=auto`，自动下载工具链 | 已解决（goose v3.29.0 可用） |
| Go 版本低于 go.mod 声明 | 需要 go1.26 工具链 | 保持 `GOTOOLCHAIN=auto`，由 Go 自动切换 | 已解决 |
| 无 Docker | compose 无法启动 PostgreSQL/Redis/MinIO | 使用 embedded-postgres 便携库 + 内存 Redis 降级 | 已解决（开发环境）；compose 仍待验证 |
| 无 psql/pg_dump/pg_restore | 备份恢复脚本无法直接执行 | 安装 PostgreSQL 客户端工具，或在有 Docker 的机器执行容器内备份 | 待解决 |
| raw.githubusercontent.com 不可达 | 无法直连 raw 文件 | 仓库内已自带全部 SQL/文档/生成代码 | 已规避 |
| npm 11 未知配置警告 | `Unknown project config` 警告 | 无害；只影响输出噪音 | 已规避 |
| 镜像未配置时安装慢/失败 | 依赖下载超时 | `npm config set registry https://registry.npmmirror.com` | 已解决 |
