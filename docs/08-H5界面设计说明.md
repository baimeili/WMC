# H5 用户端界面设计说明

> 本文档记录 H5 客户端（`app/uni-app`）的视觉设计体系、关键页面改造点，以及本次通过真实截图复核发现并修复的问题。
> 所有截图由 Playwright 在 iPhone 13 视口（390×844，DPR=2）下截取，位于 `docs/screenshots/`。

## 1. 设计目标

产品不是「刷脸 Dating App」，而是一个**数据化的婚恋市场工具**。界面必须传达：

- **理性与可信**：数字、比例、口径说明比照片更重要；
- **清晰的市场边界**：理论市场估算与本站真实用户池必须一眼可区分；
- **克制的情绪**：不用刺激性文案与强社交暗示，不制造焦虑；
- **移动优先**：单手操作、大点击区、短路径。

## 2. 视觉语言

| 维度 | 规范 |
|---|---|
| 主色 | 电光靛蓝 `#3355FF`，渐变 `#3355FF → #5A7BFF` |
| 深色底 | 深空蓝渐变 `#101A3F → #23328C → #3B57E0`（首屏 Hero、结果数字） |
| 理论市场 | 琥珀 `#F59E0B` + 浅琥珀底；语义 = 统计估算 |
| 真实市场 | 青绿 `#0EA5A5` + 浅青底；语义 = 已注册真实用户 |
| 文本 | 标题 `#0B1220` / 正文 `#334155` / 次要 `#64748B` / 弱 `#94A3B8` |
| 页面底色 | `#F4F6FB` |
| 字号 | 展示 56rpx / H1 44 / H2 34 / 正文 28-30 / 说明 22-24 |
| 圆角 | 卡片 28rpx、按钮 24rpx、标签胶囊 999rpx |
| 阴影 | 卡片 `0 12rpx 40rpx rgba(15,23,42,.08)`；主按钮彩色投影 |
| 间距 | 8 / 16 / 24 / 32 / 40 / 56rpx 节奏 |

数字统一使用等宽数字（`font-variant-numeric: tabular-nums`），保证占比、人数纵向对齐。

## 4. 本次截图复核中发现并修复的问题

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | `PageShell.vue` 里的全站样式被 uni-app 编译成 `[data-v-xxx]` 作用域样式，页面内容拿不到 | 设计系统整体失效，卡片无内边距/背景/圆角，界面接近「裸 HTML」 | 全站样式迁移到 `src/styles/global.scss`，由 `App.vue` 引入（App.vue 样式为全局）；组件只保留自身样式 |
| 2 | `App.vue` 未自动注入 `uni.scss`，直接使用 `$wmc-*` 变量导致 SCSS 编译 500、整页白屏 | 页面无法加载 | `App.vue` 显式 `@import './uni.scss'`（uni-app 只向页面/组件注入令牌） |
| 3 | 候选人卡片 `@tap` 事件与原生 tap 冒泡冲突，页面收到事件对象而不是候选人 | 点击候选人进入详情时 `id=undefined`，显示「候选人 ID 非法」 | 组件事件改名 `select` + 根节点 `@tap.stop`；发现页改用 `@select` |
| 4 | 候选人详情后端对空的 `conflicts/reasons/dimensions` 使用 `omitempty` | 前端 `candidate.conflicts.length` 抛错，「为什么匹配」整块不渲染 | 后端固定输出数组；前端增加 `safeReasons/safeConflicts/safeDimensions` 兜底 |
| 5 | 真实漏斗底部「最终值」仍显示单向人数，与第 10 层双向人数矛盾 | 数据口径自相矛盾 | 最终块改为「双向基础候选人 = reciprocal_count」 |
| 6 | 理论市场结果接口返回 `data.estimate.{...}` 嵌套结构，前端契约按平铺字段读取 | 结果页/分享页渲染报错（Cannot read properties of undefined） | 后端响应内嵌 `Estimate` 结构，字段平铺到顶层，与 OpenAPI 一致 |
| 7 | 计算器页顶部导航与页内标题重复；敏感性页标题过长换行 | 信息层级重复 | 步骤标题改为「第 N 步 · 步骤名」，卡片标题改为「基础信息/期望条件…」，敏感性页标题缩短 |

## 5. 可访问性与文案

- 主要按钮点击高度 96rpx（≈48px），符合移动端触控标准；
- 正文对比度 ≥ 4.5:1（#334155 on #FFFFFF）；
- 所有理论市场区域固定出现「统计估算/不是本站真实用户数量」说明；
- 真实市场小样本一律 `<10`，不出现「0 个人」；
- 分数名称固定为「条件契合度 / 关系观念兼容度 / 综合匹配度」，并附「不代表婚姻成功概率」；
- 不使用「剩女」「高价值男性」等价值判断词汇。
