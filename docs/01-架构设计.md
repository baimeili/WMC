# 架构设计

## 1. 总体形态

Modular Monolith（单体模块化）+ 独立前端，符合规格 §78「不擅自增加微服务」。

```
           ┌──────────────┐   ┌──────────────┐
  H5/App   │  app/uni-app │   │ admin/vue-admin │ 运营后台
           └──────┬───────┘   └──────┬───────┘
                  │  HTTPS + JSON    │
                  ▼                  ▼
            ┌───────────────────────────────┐
            │        backend (Go/chi)       │
            │  平台层 → 领域模块 → 仓储层    │
            └───┬───────────┬───────────┬───┘
                │           │           │
        PostgreSQL 18    Redis 7    对象存储(S3/MinIO/本地FS)
```

## 2. 后端分层

- **cmd**：`api`（HTTP 服务）、`worker`（定时任务）、`seed`（测试数据）、`devdb`（无 Docker 环境下的本地 PostgreSQL 启动器）
- **internal/platform**：配置、数据库、HTTP 中间件、统一响应、错误码、日志、指标、Redis 封装、枚举编码
- **internal/{auth,user,profile,preference,compatibility,calculator,matching,discovery,interaction,moderation,analytics,admin,meta}**：领域模块，每个模块含 handler / service / repo / dto
- **internal/db/sqlcdb**：sqlc 生成代码（提交入库，保证无 sqlc 也能编译）
- **internal/{storage,sms,settings,region}**：可替换基础设施抽象

依赖方向：handler → service → repo → sqlc/pgx；平台层被所有模块依赖，领域模块之间只通过 service 接口或纯函数引擎交互。

## 3. 核心引擎（纯函数、可测试、可复现）

- **Calculator Engine**：输入标准化条件 + 基线记录（或 SQL 聚合），输出总权重、顺序漏斗、Leave-One-Out 敏感性。无数据库依赖，可单元测试。
- **Matching Engine**：输入双方画像、偏好、价值观规则，输出 `Eligible`、硬条件冲突列表、条件契合度、关系观念兼容度、综合匹配度与逐维度解释。无数据库依赖。

## 4. 数据流

**理论市场估算**：请求 → 校验 → 归一化条件（生成稳定 hash）→ Redis 缓存命中？→ 数据库加权聚合 → 引擎计算漏斗与敏感性 → 落 calculator_runs 快照 → 响应。

**真实候选池**：请求 → 鉴权与入池校验 → SQL 双向硬筛（keyset 游标）→ 对候选批量加载价值观规则 → Matching Engine 计算软分与解释 → K 匿名处理 → 响应。

**互动**：PUT /interactions → upsert 自身选择 → 事务内检查对方是否已 like → 是则创建 match（唯一约束保证只有一条）→ 发产品事件。

## 5. 可替换抽象

| 抽象 | 开发/测试 | 生产 |
|---|---|---|
| SMSProvider | mock（固定验证码） | 云厂商实现（预留接口） |
| ObjectStorage | fs（本地盘 + 签名路由） | S3 / MinIO（预签名 URL） |
| Redis 客户端 | miniredis / 内存降级 | Redis 7 |
| 数据库 | embedded PostgreSQL 17（无 Docker） | PostgreSQL 18 |

## 6. 可观测性

- `GET /health/live`、`GET /health/ready`（就绪检查包含数据库与 Redis）
- `GET /metrics`：HTTP 请求数/错误率/时延直方图、数据库连接池、Redis 状态
- 结构化 JSON 日志：timestamp、level、request_id、user_id、method、path、latency、status、error_code（禁止敏感字段）
